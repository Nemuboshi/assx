# LSP Source Positions Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task by task. Each checkbox is a verification step.

**Goal:** Supply exact decoded-byte spans and UTF-16 positions for LSP without changing CLI output.

**Architecture:** Keep byte spans in ASS and lint. Convert them only in `internal/sourcepos`. Keep CLI coordinates and JSON unchanged.

**Tech Stack:** Go 1.27 standard library and existing assx packages.

**Spec:** [L02 issue #43](https://github.com/Nemuboshi/assx/issues/43)

## Global Constraints

- Keep the existing JSON schema and CLI output bytes.
- Reject invalid byte and UTF-16 boundaries. Do not round positions.
- Use decoded UTF-8 offsets. Do not use raw file byte offsets.

## Review Focus

- CRLF interior offsets must fail; EOF after a terminator is a new empty line.
- A UTF-16 position inside an emoji must fail.
- An edit that splits a UTF-8 rune must fail.
- A diagnostic without a source token must get a zero-width source point.
- A nested tag span must map to the exact document slice.

## Task 1: Line Index

**Files:** Create `internal/sourcepos/index.go` and `internal/sourcepos/index_test.go`.

**Interfaces:** `New(text string) (Index, error)`, `Index.Position(offset int) (Position, error)`, `Index.Offset(position Position) (int, error)`, `Index.Range(start, end int) (Range, error)`, `Index.EditRange(edit.TextEdit) (Range, error)`.

- [ ] Write round-trip tests for LF, CRLF, CR, tabs, Chinese text, emoji, empty input, and EOF.
- [ ] Run focused tests and confirm they fail without the implementation.
- [ ] Implement line framing and strict UTF-8/UTF-16 boundary checks.
- [ ] Run focused tests and `go test ./...`.

## Task 2: Diagnostic Spans

**Files:** Modify `internal/lint` creation sites and tests, `internal/lintreport/build.go`, and syntax/report docs.

**Interfaces:** `lint.Diagnostic.SourceSpan` remains the decoded-byte range; legacy JSON must omit newly populated spans.

- [ ] Write failing tests for source slices of tag, style, event, and document diagnostics.
- [ ] Populate spans where concrete syntax or parsed fields establish them.
- [ ] Keep point spans for missing source and preserve presenter fallbacks.
- [ ] Run CLI golden tests, `go test ./...`, `go vet ./...`, and build.

## Task 3: Review and Integration

- [ ] Review all changed files and check malformed ranges and unchanged JSON bytes.
- [ ] Run `go test ./...`, `go vet ./...`, build, and `git diff --check`.
- [ ] Commit only L02 changes. Do not close #43 until its acceptance tests pass.
