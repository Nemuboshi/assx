# LSP L04-L10 Implementation Plan

> **For agentic workers:** Use the executing-plans skill. Complete each task in order. Test and commit each finished task.

**Goal:** Complete the renderer-aware LSP epic in issues #45-#51.

**Architecture:** Keep the LSP transport and adapters in `internal/lsp`. Reuse `internal/analysis`, the lossless ASS syntax tree, renderer profiles, and proof APIs. Do not add a second ASS grammar or an editor-side semantic engine.

**Tech Stack:** Go 1.27, LSP 3.17 over stdio, TypeScript for the VS Code adapter.

**Spec:** https://github.com/Nemuboshi/assx/issues/41 and child issues #45-#51.

## Global Constraints

- Preserve CLI behavior and renderer proof scope.
- Do not read files during an LSP document request.
- Do not offer an edit without current, renderer-scoped SafeFix proof.
- Use UTF-16 positions and versioned document edits.
- Keep stdout exclusive to JSON-RPC frames.

## Review Focus

- A stale version or settings change must not produce an edit. Test L05.
- A conditional renderer signature must not appear verified. Test L06 and L08.
- Duplicate Style names must not create false navigation. Test L07.
- Malformed and partial syntax must not panic. Test L06, L08, and L09.
- The VS Code adapter must not duplicate Go parsing or diagnostics. Check L10.
